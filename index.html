🎓 Ontology-Based Educational Framework

Intelligent, Explainable, Personalized Learning Path Generation

This interactive demonstration showcases an ontology-based framework for personalized educational process planning. The system uses semantic reasoning (OWL, SWRL, SPARQL) to generate individualized learning paths based on competency prerequisites, learner profiles, and educational standards (Bloom's Taxonomy, EQF, IEEE LOM).

System Overview

This demonstration implements the ontology-based framework described in the research article. The system integrates four semantic layers to enable automated, explainable personalized learning:

1️⃣ Learner Layer

Models individual characteristics: learning styles (VARK), mastered competencies, goals, and preferences.

2️⃣ Competency Layer

Encodes learning outcomes with Bloom's cognitive levels, EQF qualification levels, and transitive prerequisite relationships.

3️⃣ Content Layer

Describes educational resources (courses, modules) using IEEE LOM standards, mapped to competencies.

4️⃣ Process Layer

Generates personalized learning paths through hybrid reasoning: OWL inference, SWRL rules, SPARQL queries.

      Step-by-Step Reasoning Pipeline

      1
      🔍 Query Learner Profile
      System retrieves learner's characteristics: mastered competencies, learning style (VARK model), target goal, and time availability. This data is stored as RDF triples in the ontology.
      Example Query:
      SELECT ?learner ?mastered ?style ?goal WHERE { ... }
      ⬇
      2
      🔗 OWL Reasoning: Transitive Closure
      The OWL 2 DL reasoner computes transitive prerequisite relationships. If A requires B, and B requires C, then A transitively requires C. This inference happens automatically through the requiresCompetency transitive property.
      OWL Axiom:
      requiresCompetency rdf:type owl:TransitiveProperty
      ⬇
      3
      📊 Gap Detection (SPARQL Query 2.1)
      System executes SPARQL query to find competencies required for the goal that the learner hasn't mastered. Gaps are categorized as high priority (direct prerequisites) or medium priority (indirect prerequisites).
      Detection Logic:
      Gaps = (Required Competencies) ∩ ¬(Mastered Competencies)
      ⬇
      4
      🔀 Topological Sorting
      To create a valid learning sequence, the system performs topological sort on the prerequisite graph. This ensures that prerequisites are always scheduled before dependent competencies, preventing circular dependencies.
      Algorithm: Kahn's Algorithm with priority weighting
      ⬇
      5
      📚 Resource Matching (SWRL Rules)
      For each competency in the sorted path, SWRL rules select appropriate learning resources. Rules consider: (1) which resources teach the competency, (2) learner's learning style preference, (3) difficulty level matching learner's performance.
      SWRL Rule Example:
      Learner(?l) ∧ hasStyle(?l, Visual) ∧ Resource(?r) ∧ suitableFor(?r, Visual) → recommendedFor(?r, ?l)
      ⬇
      6
      💬 Explanation Generation (SPARQL Query 3.1)
      The system generates natural language explanations by tracing prerequisite chains through SPARQL queries. For each recommended resource, it explains WHY it's needed by identifying the path from current competencies to the goal.
      Output: Natural language reasoning traces with clickable node explanations

      🎯 Key Advantages of This Approach

      • Explainability: Every recommendation includes a traceable justification based on prerequisite logic.
      • Consistency: OWL reasoning guarantees logically valid prerequisite structures (no cycles, complete coverage).
      • Adaptability: SWRL rules enable context-sensitive personalization (learning styles, difficulty matching).
      • Standards Alignment: Bloom's Taxonomy and EQF levels ensure pedagogical validity.
      • Interoperability: RDF/OWL format allows integration with other educational systems and data sources.
      • Interactive Exploration: Visual graph interface with filtering and real-time path generation.
